# 训练计划 Excel 导入说明

适用协议：`planner-import-v2 / 2.0 / FROZEN`。Excel 的 `schemaVersion=2` 是导入协议版本，训练器用户状态仍为 Schema 6，两者不要混淆。

协议真源：[PLANNER_IMPORT_V2_SPEC.md](../../planner-protocol/PLANNER_IMPORT_V2_SPEC.md)。本说明是填写指南，不定义另一套协议。新模板、示例均保留现有 10 张 Sheet、全部字段、列顺序和英文 enum；没有新增机器字段。

核对时发现一处既有可选默认值差异：SPEC 给 `计划信息_v2.locale` 的默认值是 `zh-CN`，当前导入器留空时返回空字符串。本轮两份文件均显式填写 `zh-CN`，避免依赖该差异；不改冻结协议或扩展修改导入器默认值。Sheet、列及必填定义一致。

## 文件用途

- `训练计划导入模板-V2.xlsx`：填写新计划。计划信息中的 `PLAN_KEY`、计划名称等占位值需要替换；其余机器表只有表头，没有训练内容，不能直接正式导入。
- `训练计划导入示例-V2.xlsx`：匿名接口演示，可用于验证导入。不是你的个人训练处方；包含四个训练日、热身、正式组、超级组、递减、活动和作用范围说明。

不要直接改已有用户存档，也不要把真实训练重量、实际日期或日志写进 Excel。

## 固定工作表与必填字段

| Sheet（顺序固定） | 用途 | 有数据行时必填 |
|---|---|---|
| 填写说明 | 人工阅读的规则和逐字段说明，不是训练内容 | 无机器字段要求 |
| 计划信息_v2 | 计划身份，必须且只能一行 | protocol、schemaVersion、planKey、planVersion、programName |
| 训练日_v2 | 一行一个 Workout | planKey、planVersion、workoutKey、order、workoutType、title |
| 动作_v2 | 一行一个独立 Exercise | planKey、planVersion、workoutKey、exerciseKey、order、section、trainingRole、exerciseType、name、trackingName、countsAsWorkingSet、countsAsHypertrophySet |
| 组计划_v2 | 一行一组，保存计划目标 | planKey、planVersion、workoutKey、exerciseKey、setKey、setNo、setType |
| 超级组_v2 | 组成员执行规则 | planKey、planVersion、workoutKey、supersetKey、mode |
| 递减组_v2 | 一行一个递减阶段 | planKey、planVersion、workoutKey、exerciseKey、parentSetKey、dropSegmentKey、segmentOrder |
| 活动_v2 | 热身、有氧、攀岩、技能或恢复 | planKey、planVersion、workoutKey、activityKey、order、activityType、name |
| 活动阶段_v2 | 活动的热身阶段或 drill | planKey、planVersion、workoutKey、activityKey、activitySegmentKey、segmentOrder、segmentType、name |
| 说明块_v2 | 不生成动作卡的说明 | planKey、planVersion、instructionKey、scopeType、scopeKey、order、instructionType、content |

全部机器列的类型、范围和默认值见 SPEC 及 Excel「填写说明」。表头颜色只帮助识别必填列，不改变机器列名。下拉选项是输入辅助，正式导入仍以 Validator 为准。无内容的机器表必须保留表头；不能增加第 11 张 Sheet。

条件规则尤其需要注意：

- Set 必须且只能填写 `repsMin/repsMax` 或 `durationSec`。同一种范围上下限要一起填写。
- `targetWeight` 有值时需要 `weightUnit=kg/lb`；数值与单位分开。目标重量不会填进实际 `weight/weightKg` 或历史日志。
- RIR/RPE 上下限在 0–10；休息、时间和计量范围非负，`durationSec` 必须大于 0。
- `supersetKey` 有值时，`supersetOrder` 必填。
- 重量调整类型和值同时填写；递减第 1 段不填重量调整，第 2 段起必须填调整类型、上下限。
- Activity 有计量范围时要填 `measureUnit`；cardio 至少有 duration 或 measure。
- 日期写 `YYYY-MM-DD` 文本；时间单位秒，唯独 `targetDurationMin` 为分钟。
- `protocol=planner-import-v2`，协议 `schemaVersion=2`；所有行的 planKey/planVersion 一致。
- 布尔字段只用 TRUE/FALSE，enum 只使用下拉中的英文值。空白选填字段真正留空，不填“无”、N/A 或“-”。

## 动作名称与备注

推荐直接分开填写：

| name | trackingName | note |
|---|---|---|
| 杠铃卧推 | 杠铃卧推 | 控制下降3秒 |
| 深蹲 | 深蹲 | RPE 8 |
| 罗马尼亚硬拉 | 罗马尼亚硬拉 | 注意髋部后移；保持背部稳定 |

`name` 只填写正式动作身份。执行方法、呼吸、节奏和注意事项填写 `note`，技术提示也可填写既有 `techniqueCue`。Set 级技术提示写到 `组计划_v2.techniqueCue`。

希望独立历史的动作使用明确名称，例如「杠铃卧推」「窄握杠铃卧推」「暂停杠铃卧推」，不要把变式身份藏在括号里。相同名称的两条 Exercise 仍由不同 exerciseKey 区分，不会被合成一条。

### 动作名称与备注兼容规则

本文件对应发布 Build `20261014-planner-name-notes-1`。模板将动作身份与执行备注分开；旧版 Planner v2 文件保持兼容。

本轮本地兼容处理只针对 `动作_v2.name`：

- 支持中文圆括号 `（）`、英文圆括号 `()`、中文方头括号 `【】`，包括连续多块和成对嵌套。
- 括号内容追加到 `note`，保留原备注；相同分项不重复追加。只清理必要的首尾空白，用「；」连接不同说明。
- trackingName 列必须保留。没有显式填写值时，使用规范化后的 name 作为历史追踪名称；这是输入兼容补全，不增加字段或改变 canonical trackingName 必须存在的要求。
- 显式 trackingName 始终保留，即使它完全等于带括号的原 name。含括号时导入预览提示人工确认，不自动改写。建议默认填写规范 name，不要随备注变化修改历史身份。
- 空名称、整段名称只有括号、括号不配对，要求人工确认，不能生成空动作。
- 括号里有组数、次数、重量、百分比、总时长、RIR 时会报错要求规范录入组计划；不会从文字推断或覆盖处方参数。
- 「控制下降3秒」这类执行节奏与总动作时长不同，保存在备注，不改 `durationSec`。「RPE 8」是 Exercise 自由说明，不能自动转换成 RIR；有氧/攀岩的结构化 RPE 使用 Activity 字段。

不会全局删除括号，也不会处理计划名、训练日标题、来源键、ID、Activity 名称或已有用户历史。旧日志里已经夹带备注的历史名称，本轮不清理、不自动对齐。

## 稳定身份与版本

所有来源键以大写英文字母开头，只含 A–Z、0–9、下划线或连字符，最长 64 字符，同一本 Workbook 内全局唯一。

示例：`W001` → `W001-E01` → `W001-E01-S01`。它们是来源键，不是训练器内部 workoutId/exerciseId/setId。

planKey 标识计划谱系，内容更新时保持不变；planVersion 使用 `1.0`、`1.1`、`1.0.0` 等格式。备注、标题、排序变化不重生成来源键。删除的 key 不复用；不同实体不要共用 key。

历史重量主要按 trackingName 的统一标准化名称跨 Program 查询，训练执行、Draft 和日志 ownership 仍保留各自稳定 ID。备注拆分不会迁移或重命名旧日志。新文件也不能提供 actualDate、completed、workoutLogs 等执行状态。

## 热身填写

主项热身使用 `活动_v2` 一行定义 `activityType=warmup`，例如「杠铃卧推｜主项热身」；在 `活动阶段_v2` 用同一个 activityKey 定义各阶段，`segmentType=warmup-stage`，segmentOrder 从 1 连续。

热身 Activity 至少一个阶段。阶段各自保存目标重量、次数、休息、技术提示和独立 key。不要把热身标题作为正式动作。两个主项分别使用两个 Activity。

如需演示同一训练动作的预备组，可在 `组计划_v2` 中使用 `setType=warmup`。它与 working/technique/top/backoff 一样一行一组，不在一个单元格写整套组数。

## 超级组与递减组

超级组先在 `超级组_v2` 定义 supersetKey，当前 `mode` 只允许 `alternating`。各动作通过 `动作_v2.supersetKey + supersetOrder` 引用同一组，至少两个成员，必须属于同一 Workout。动作、Set、名称和历史身份保持独立。

动作间过渡使用 transitionMinSec/transitionMaxSec，轮间休息使用 roundRestMinSec/roundRestMaxSec。每个成员在组计划中分别填写各轮的组，不能用「A/B 连续做」替代结构化关联。

多阶段递减使用 `组计划_v2.setType=dropset` 作为父组，在 `递减组_v2` 每行写一个阶段，并引用同一 parentSetKey。至少两段，segmentOrder 连续。百分比调整用 `percent`，例如 -25 至 -20；不把「-20%」写成带单位的数字字符串。

## 活动、说明与休息日

Zone2、有氧、攀岩、恢复使用 Activity。攀岩阶段可以使用 drill/route-block；不要伪装成 Exercise。

说明块通过 scopeType=workout/exercise/activity 和 scopeKey 挂到对应实体，不产生假训练动作。

`workoutType=rest` 不允许 Exercise、Set、Superset 或 Drop；Activity 只能是 recovery，也可以没有 Activity。

## 导入步骤

1. 复制模板填写一个新文件，保留原模板；删除或替换计划信息占位值。
2. 先填训练日，再填动作、Set、活动及相关关联表。
3. 检查名称与备注分开，来源键、英文枚举、外键、顺序和数值范围正确。
4. 在训练器导入页选择 Excel，查看「Planner Import v2」预览和统计。
5. Errors 必须为 0，Semantic validation 必须为 PASS。Warnings 应逐项检查。
6. 人工选择「导入为新的训练计划」。确认新计划后切换使用，不自动替换旧 Program。

完全相同内容沿用现有重复检测。备注变化属于内容版本差异，可以作为新的 Program，经人工确认导入；不会自动覆盖旧计划、复制旧日志或合并 Draft。用完保留完整备份。

## 常见错误

- 改 Sheet、表头、列顺序或新增说明列：机器表严格校验，说明应写在既有 note/techniqueCue 或「填写说明」。
- 把 Excel 协议 schemaVersion 填成 6：正确值是 2，应用状态的 Schema 6 不填进此字段。
- planVersion 被转成数字 1：按文本填写 `1.0`，模板已设置文本格式。
- source key 随机重生成、重复或外键引用错父级：先修 key，不通过名称猜关联。
- 同时填写 reps 与 duration、范围只填一端或枚举用中文：按 SPEC 改回结构化值。
- 在 name 中写 `3x5`、`60kg`、`30秒`：搬到正确组计划字段，不让导入器猜训练参数。
- 空白模板直接导入：只有结构没有训练内容，不能通过正式导入门槛。
- 把重复名称视为重复日志：Exercise 身份由 key 区分，导入计划本身不生成 workoutLogs。

本次发布仅更新导入兼容代码与交付文件；不会操作真实手机 IndexedDB、旧 ROOT 或已有训练历史。
